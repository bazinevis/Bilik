Each enumerator corresponds to a specific relationship between elements in a document's structure. Let's break down each enumerator and provide CSS examples for each.


Breakdown of the Enum Class
1. Descendant (E F):
This combinator matches elements that are descendants of a specified element. It means that the second element can be any level deep within the first element.
CSS Example:
div p {
  color: blue; /* This will style all <p> elements that are inside any <div> */
}

2. Child (E > F):
This combinator matches elements that are direct children of a specified element. The second element must be an immediate child of the first element.
CSS Example:
ul > li {
  list-style-type: square; /* This will style only the <li> elements that are direct children of a <ul> */
}

3. NextSibling (E + F):
This combinator matches an element that is immediately preceded by a specified element. The second element must be the next sibling of the first element.
CSS Example:
h1 + p {
  margin-top: 0; /* This will style the <p> element that directly follows an <h1> */
}

4. SubsequentSibling (E ~ F):
This combinator matches all elements that are preceded by a specified element, but not necessarily immediately. The second element can be any sibling that follows the first element.
CSS Example:

h2 ~ p {
  color: green; /* This will style all <p> elements that follow an <h2> element, not just the first one */
}

/* Attribute selector examples */

The AttributeSelectorType enum defines different types of attribute selectors in CSS, which allow you to select elements based on their attributes and attribute values. Here’s a breakdown of each type along with examples. This says that if attribute of specified tag is equal or not equal or begins or ends with sth or etc, select that.
1. Always (used in code)
Description: This type is used to indicate that the attribute selector always matches, regardless of the attribute's value.
Example: This is more of a conceptual type rather than a direct CSS selector.
IN CODE rmlui uses AttributeSelectorType::Always enum value to indicate a initial value to this type of selector so when checking is there a attribute selector if we encounter AttributeSelectorType::Always value we know there is not any.

2. Equal (=)
Description: Matches elements with an attribute that has an exact value.
Example:
input[type="text"] {
  /* Matches <input> elements where type is exactly "text" */
}
3. InList (~)
Description: Matches elements with an attribute whose value is a space-separated list of words, one of which matches the specified value.
Example:
div[class~="highlight"] {
  /* Matches <div> elements that have a class attribute containing "highlight" as one of the classes */
}
4. BeginsWithThenHyphen (|)
Description: Matches elements with an attribute that starts with the specified value followed by a hyphen.
Example:
a[href|="en"] {
  /* Matches <a> elements where href is "en" or starts with "en-" */
}
5. BeginsWith (^)
Description: Matches elements with an attribute whose value begins with the specified value.
Example:
img[src^="https://"] {
  /* Matches <img> elements where src starts with "https://" */
}
6. EndsWith (\$) (dollor sign)
Description: Matches elements with an attribute whose value ends with the specified value.
Example:
a[href\$=".pdf"] {
  /* Matches <a> elements where href ends with ".pdf" */
}
7. Contains (*)
Description: Matches elements with an attribute whose value contains the specified value anywhere within it.
Example:
div[data-info*="important"] {
  /* Matches <div> elements where data-info contains the word "important" */
}
Summary
The AttributeSelectorType enum provides a way to create powerful and flexible selectors based on the attributes of HTML elements. By using these selectors, developers can target elements more precisely based on their attributes and values, enhancing the ability to style and manipulate elements in a web document.

\subsection{Selector Specifity}
Specificity in CSS is a mechanism that determines which styles are applied to an element when multiple rules could apply. It helps resolve conflicts between selectors by assigning a weight to each selector based on its components. Here’s a breakdown of its importance:

1. Conflict Resolution: When multiple CSS rules apply to the same element, specificity helps determine which rule takes precedence. The rule with the highest specificity will be applied.

2. Hierarchy of Selectors: Specificity allows for a clear hierarchy among different types of selectors. For example, IDs are more specific than classes, and classes are more specific than tags. This hierarchy helps developers manage styles effectively.

3. Maintainability: Understanding specificity can help developers write more maintainable and predictable CSS. By knowing how specificity works, developers can avoid overly complex selectors and ensure that styles are applied as intended.

4. Debugging: When styles are not applied as expected, understanding specificity can help identify why certain styles are overridden. This can make debugging CSS issues much easier.

5. Performance: While specificity itself doesn't directly impact performance, using overly specific selectors can lead to more complex stylesheets that are harder to manage and may slow down rendering in some cases.

In summary, specificity is crucial for controlling which styles are applied to elements, making CSS more predictable and easier to manage.
